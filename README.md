# 阿浪 · B 站游戏区冲浪 agent

一个自己出门刷 B 站游戏区的 agent：自己挑题、自己调工具、自己写日记、自己改口味。

**代码不替它选题。** 每整点它自己出门一趟（也能手动触发，或在你说话／给反馈后触发），
自己决定搜什么词、刷哪个分区、精读哪条、要不要改兴趣画像。后端只给两样东西：
手脚（六个工具）和记忆（SQLite + 本地向量）。

这是一个 demo：没有多用户、没有登录、没有并发优化。取舍全部朝「跑起来能看懂」倾斜。

---

## 三个设计决定

后面所有细节都从这三条推出来。

### 1. 绝不把「没抓到」读成「没有」

这是整个项目最硬的一条。**它写的日记，下一轮会被当上下文读回来**——一次把限流读成
「这类内容没人看」，那条错误认知就会在第 2、3、4 轮里越长越结实。所以空结果和失败
在这套代码里从头到尾是分岔的：

| 真实情况 | 怎么表示 | 喂给模型的话 |
|---|---|---|
| 搜索被软限流挡下 | 抛 `BiliThrottled`，动作记 `n=-1`（与真搜到 0 条的 `n=0` 分开） | 「这次被挡了，不代表这个词没内容，别写进日记」 |
| 评论接口在限流 | 单独留 `comments_error` 字段，不吞成空列表 | 「评论这次没抓到，不代表这视频没人评论」 |
| 接口不接受这个 rid | 前置拦下，不让下游抛异常再分辨 | 「是接口不认这个 rid，不是该分区没有新投稿」 |
| 分区名查不到 | 渲染成 `未知分区(tid=N)`，绝不留空串 | 空串会被读成「分区就是空的」；猜错的名字更糟，那是一条错误知识 |
| 视频刚发布，播放和评论真是 0 | 每条都带相对时间（「3 分钟前」） | 它才分得清「是刚发」还是「没抓到」 |

判据也统一成一条：**看键在不在，不看值真假**。真搜到 0 条时 `numResults` 的值是 0
（假），而限流时这个键整个不见了——用取值判断会把两者正好判反。

工具分发表的兜底 `except` 同样要交人话出去（`工具执行异常：KeyError ...`），
静默吞成空返回才是真正危险的写法。

### 2. 上下文是预算，不是垃圾桶

精读一条视频能抓回几千字。工具循环每一轮都要把历史重发一遍，全塞进去，代价是平方级的。

所以正文全部落 `chunks` 表（带向量），**只把摘要和最热几条评论还给模型**；要细节它自己
调 `recall_memory` 做语义检索。评论按 10 条一组分块存——一个向量表示不了几十个话题，
整坨存进去只会把相似度摊薄，捞出来又长又不对题。

量级没到之前，向量库是纯负债：检索就是几千条以内的暴力余弦，`numpy` 一次矩阵乘。

### 3. 它会照镜子

同一个词连搜七遍、一直在同一个分区打转，是这类 agent 最典型的自锁。两处对症：

- **换 `order`。** 同一个关键词，`pubdate` 序和默认相关度序几乎是两批人（实测只重叠
  1/20）。工具描述里就写明：「一个词搜过一遍后，与其原样再搜，不如换 order 或换词。」
  换 order 只换人、不换话题，两者是两件事。
- **把计数摆给它看。** 出门前附一段「你最近几次动作」的计数：搜索几次、同一个关键词占了
  几路、已读视频的类型分布。**只陈述计数，不评价、不指路**——判断留给它自己下。

## 对照实验

口口声声说「用户反馈在塑造它的口味」，那就得能验。

`POST /api/ablation` 会把 `feedback` 表整个屏蔽，在同样的状态下再出门一趟，把两轮的工具
调用并排摆出来；差出来的那些动作，就是反馈真正改变的部分。

它走的是同一套代码路径，只是跳过了写库那一步（`dry_run=True`）——不是另写一份模拟，
是真跑了一次，只是没留痕。

## 跑起来

需要 Python 3.10+（开发环境 3.11.6）。

```bash
pip install -r requirements.txt
```

> `sentence-transformers` 会顺带装进 `torch` 和 `transformers`（本机实测
> `torch==2.13.0` / `transformers==5.15.0`），体积不小。这两个故意没写死在
> `requirements.txt` 里——它们版本敏感，交给 pip 去解析；真跑不起来时再照上面
> 两个版本回钉。
>
> `requirements.txt` **必须保持纯 ASCII**：pip 按系统区域编码读它，在 GBK 的
> Windows 上，一个中文注释就会让 `pip install -r` 直接抛 `UnicodeDecodeError`。

在项目根目录建 `.env`（**已被 .gitignore 排除，别提交**）：

```ini
DEEPSEEK_API_KEY=sk-...              # 必填，没有它启动会直接退出
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash

BILI_SESSDATA=...                    # 可选，见下
BILI_COOKIE=...                      # 可选，从 devtools 整行复制的 cookie

SURF_INTERVAL_SECONDS=3600           # 多久自己出门一趟
SURF_READ_PER_ROUND=12               # 每轮精读上限
DAILY_TOKEN_BUDGET=600000            # 每日 token 上限，超了就停
```

```bash
python backend.py
```

浏览器开 <http://127.0.0.1:8000>。

> 改完代码必须**重启进程**才生效：`init_db()` 和调度线程都在
> `if __name__ == "__main__"` 里，所以没有 `--reload` 这条路可走。

### 为什么建议填 SESSDATA

未登录也能刷榜（96 条）、能搜（20 条）、能拿弹幕（几百条），**唯一被卡死的是评论**：
服务端只给 3 条预览，`ps` 给多大都没用——那是授权门槛，不是限流。而评论是这里唯一
有实际内容的长文本，没它 RAG 的语料薄得像纸。填 SESSDATA 是性价比最高的一步。

## 采集层自检

```bash
python crawler.py
```

不碰数据库，只读地打一遍 B 站接口，打印：登录态、排行榜条数、搜索、精读（含分区名）、
以及「最新投稿和热度榜是不是两批池子」。**B 站接口一有变化，先跑它。**

## 已知限制

- **评论翻页没打通。** 第二页改用 `pagination_str` 传 cursor 后，接口 `code=0` 不报错，
  却每次把第一页原样再发一遍，去重后一条新的都没有（紧凑 JSON 也试过，不是空格编码
  问题）。翻页逻辑在 `comments()` 里留着但默认关着——**别把 `limit` 调大，那只是每条
  视频白打 1~2 个请求**。
- 采集层是**只读**的：只调公开接口，不登录不发帖，请求间隔 ≥1 秒带抖动，失败指数退避，
  单次运行在百次以内。
- 单进程、单用户，没有并发优化。

## 文件

| 文件 | 职责 |
|---|---|
| `crawler.py` | B 站只读采集层：WBI 签名、cookie 预热、限速退避、错误分类。不碰数据库、不碰 LLM |
| `backend.py` | FastAPI + SQLite + LLM 工具循环 |
| `envfile.py` | 手写 `.env` 解析（backend 与采集层自检共用） |
| `index.html` | 前端：日记、聊天、口味画像、已读视频 |
| `surf.db` | 运行时数据库（`-wal` / `-shm` 是伴生文件，一并忽略） |

**单文件不超过 800 行**是硬约束——加东西前先 `wc -l` 算预算。到天花板时正确的反应是
压写法、合并函数，不是拆文件。
